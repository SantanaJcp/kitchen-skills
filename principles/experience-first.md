# Experience First

- **Parent:** `design` ([PRINCIPLES.md](../PRINCIPLES.md))
- **When:** product, UX or feature-scope tradeoffs.

When implementation convenience conflicts with the user's experience, choose the experience.

- Every feature, control and option must justify itself. Fewer, finished features beat many rough ones.
- Prototype before committing: a design decision is cheaper in a throwaway sketch than in production code.
- Get the details right: transitions, alignment, feedback, error states.
- Tighten the core loop; a feature serves the central workflow or gets out of its way.

The user is whoever consumes the work: the person using the UI, the colleague who imports the library, the next maintainer. Weigh their experience the same way. Foundational thinking sets the order of the work; this sets its target.
