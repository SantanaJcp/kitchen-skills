# models

- **Reached by:** `kitchen models [get|set|add|remove] reviewer --author … [--json|--t3|--command]`, `kitchen models set worker …`, `kitchen models set|remove worker --project <name> [--accounts …]`, `kitchen models get worker --job … [--urgent] [--index N] [--project <name>] [--json|--t3|--command]`
- **Observable result:** the reviewers per author family, one per line, each with its CLI call; an unset reviewer prints none (`--t3` `{}`, `--json` `[]`, `--command` nothing), exits 0 and says on stderr that the review runs on the session model, not cross-model, with the command that sets it; `--t3` prints each reviewer's `delegate_task` target; a reviewer of the author's own family is refused, pi judged by its model; a pi call on an id pi does not list exactly is refused. The worker's effort set by the job (judgment keeps the configured one, routine one step lower, hardest one higher) between low and max, fast only with `--urgent`, accounts alternated by index over the project's own account list when it has one (the project from `--project` or the current checkout's folder; a linked worktree gets the default list unless `--project` names its project) or the default list otherwise, so an account listed only under a project is never picked outside it; `--json` names the project and the list; its `delegate_task` target per provider; an unset worker prints an empty target and says on stderr it runs on the session model
- **Proved by:** tests/test_commands.py (ModelsTests)
